// creating a context using createContext(), 
// providing the data using a Provider component,
//  and accessing the data in child components using useContext() or Consumer.

// Local Storage is a feature of the browser that allows web 
// applications to store data on the user’s device in the form
//  of key–value pairs. It is part of the Web Storage API and is 
// mainly used for storing data on the client side without involving
//  a server. The data stored in local storage does not expire 
// automatically, which means it remains available even after 
// refreshing the page, closing the browser, or restarting the system.
//  Since local storage can only store data in string format, 
// complex data types like arrays and objects must be converted 
// into strings using JSON.stringify() before storing and converted
//  back using JSON.parse() when retrieving. It is widely used in 
// modern web applications, especially in frameworks like React, 
// to persist user data such as themes, preferences, and todo lists. 
// However, since it is not secure, sensitive information like
//  passwords should not be stored in local storage.

// Key Points
// Stores data in key–value pairs
// Data is stored on the client (browser)
// No expiration time (persistent storage)
// Stores only strings
// Uses:
// setItem() → to store data
// getItem() → to retrieve data
// removeItem() → to delete specific data
// clear() → to delete all data
// Requires JSON.stringify() and JSON.parse() for objects/arrays
// Common uses:
// Saving todos
// Storing themes (dark/light mode)
// User preferences
// Not secure, so avoid storing sensitive data
//--------------------------------------------------------------------------------

// Redux is a predictable state management library used in
//  JavaScript applications, especially with React,
//  to manage global application state in a centralized way.

// Instead of storing data in individual components, 
// Redux stores all shared data in one central place called the Store.
// Think of Redux as a central brain of your application that
//  controls and remembers everything.

//In React, components manage their own state using useState.

// But in large apps:

//  Problems arise:
// Prop drilling
// Passing data through many nested components becomes messy.
// Unpredictable state changes
// Multiple components can update data in different ways.
// Hard debugging
// You don’t know who changed what and when.
// State duplication
// Same data stored in multiple components.

// Redux solves this by:
// Centralizing all state in one place
// Making state updates controlled and predictable
// Enforcing a strict pattern for updating data

//Redux Toolkit (RTK) is the official and modern way of 
// writing Redux logic in React applications. 
// It is a set of tools provided by the Redux team 
// to simplify state management and reduce the complexity of
// traditional Redux. Earlier, Redux required a lot of boilerplate
// code such as separate files for actions, reducers, and constants,
// along with complex store setup, which made it difficult
// to learn and use. RTK solves these problems by providing 
// built-in functions like configureStore() for easy store creation, 
// createSlice() to combine reducers and actions in a single place, 
// and createAsyncThunk() to handle asynchronous operations 
// like API calls. It also includes Immer internally, which allows
// developers to write simpler “mutating-like” code while still 
// maintaining immutability behind the scenes. Because of these improvements,
//RTK makes Redux faster to develop, easier to understand, and the recommended 
//standard for managing global state in modern React applications.



//When Redux was introduced, its setup took more time compared to Context API,
// and there were also problems in debugging the application. 
// To solve these issues, developers introduced Redux Toolkit (RTK), 
// which made setup and debugging much easier using built-in Redux 
// functions and simplified patterns. Because of this, state management 
// in React became more efficient and less complex. 
// That is why Redux Toolkit is now recommended for using 
// Redux in modern applications, and both Redux and Redux Toolkit 
// are commonly installed together when working on Redux-based projects.

//redux-toolkit.js.org
//redux.js.org


//React Redux is the official binding library between React and Redux. 
//It connects a React application with the Redux store so that React 
//components can access and update global state easily.




//Flux is an application architecture (design pattern) introduced
//  by Facebook for managing data flow in front-end applications,
//  especially React.

//Flux is a way of organizing how data moves in an application using a 
// one-way (unidirectional) data flow.

//Flux Problems with Redux Solutions 

// Problem: Flux had multiple stores, causing scattered and inconsistent state
// → Solution: Redux uses a single global store, making state
//  centralized and easy to manage

// Problem: Flux required a dispatcher, adding extra complexity
// → Solution: Redux removes the dispatcher and uses a simpler dispatch
//  → reducer flow

// Problem: Debugging in Flux was difficult due to complex data flow
// → Solution: Redux provides predictable state updates and DevTools,
//  making debugging easier

// Problem: Data flow in Flux was harder to track despite being unidirectional
// → Solution: Redux enforces a strict and simple unidirectional 
// flow (action → reducer → store)

// Problem: Flux structure was complicated and hard for beginners
// → Solution: Redux offers a simpler and more structured approach

// Problem: State updates in Flux could be less predictable
// → Solution: Redux uses pure functions (reducers) for consistent 
// and predictable updates

//--------------------------------------------------------------------------

// state is stored. In RTK, it is created using configureStore()

// useSelector
// useSelector is a React hook used to read data from

// parts of the state and automatically re-renders when that data changes.

//useDispatch
// useDispatch is a React hook used to send actions to the 
// Redux store. It triggers reducers to update the state 
// based on the dispatched action.
